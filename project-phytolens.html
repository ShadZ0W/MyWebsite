// 01. PROBLEM & SYSTEM OBJECTIVE

The Challenge with Traditional On-Device Classifiers

Most mobile botanical applications rely on local, edge-quantized Convolutional Neural Networks (CNNs). While fast, these static classifiers have rigid taxonomic boundaries and frequently fail when leaves are photographed under suboptimal conditions—such as indirect sunlight, shadows, wilting, or partial leaf occlusions.

Furthermore, traditional classifiers only output a categorical label (e.g., "Pandan - 82%"). They cannot evaluate nuanced questions like whether chlorosis is caused by nitrogen deficiency or fungal rot, nor can they output context-aware steps for soil remediation.

Core Objective: Build a responsive Android client capable of acquiring camera frames, performing pre-flight sanity checks, streaming data to Google's multimodal models, and deserializing actionable botanical intelligence into an intuitive user interface.
// 02. PIPELINE & FLOW

End-to-End Processing Architecture

The application isolates background tasks to prevent main-thread UI stalling during camera processing and network calls:

STEP 01

Frame Ingestion & Pre-Processing

Captures hardware camera bitmap buffers via Camera2. Automatically runs dimension downsampling and JPEG compression to keep network payloads under latency targets while preserving leaf vein micro-structures.

STEP 02

Orchestrated Prompt Payload

Constructs an engineered multimodal prompt payload sent to the Gemini API. Enforces a strict response schema covering scientific nomenclature, common variations, anomaly indicators, and practical care recommendations.

STEP 03

Payload Parsing & View Rendering

A background worker receives the stream, parses the structured response, and updates the Android UI state using asynchronous callbacks to eliminate UI freezing during long inferences.

STEP 04

Cloud History Synchronization

The query result, confidence score, and timestamped capture metadata are synchronized with Firebase Cloud Firestore, enabling longitudinal health tracking of specimens across weeks.

// 03. IMPLEMENTED CAPABILITIES

Core Engineering Highlights

Camera Pre-Flight Guidance

Integrated real-time compositional tips and focus checks in the viewfinder to guide users on lighting, distance, and orientation before sending data to the API.

Defensive Edge-Case Handling

Trained prompt constraints to defensively reject non-organic specimens, artificial items, or heavily degraded imagery without wasting inference tokens on hallucinated diagnoses.

Offline Cache & History Vault

Built local SQLite caching with Cloud Firestore syncing so previous analysis results, tips, and articles remain readable even when mobile connectivity drops.

Full SDLC & Validation

Executed over 20 structured verification cases verifying API timeout resilience, schema format parsing, and UI state restoration across device rotations and low-memory kills.

// 04. REFLECTION & TAKEAWAYS

Engineering Insights

Developing PhytoLens showcased the practical balance between on-device hardware constraints and cloud AI inference. Managing thread boundaries, preventing network memory leaks in Android Java, and designing structured prompt schemas formed the groundwork for subsequent work on low-latency systems and robotics.
